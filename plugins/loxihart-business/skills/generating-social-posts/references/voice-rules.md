# Voice Rules — Kyle Rosebrook (Extended)

Compact version lives in SKILL.md. Load this file for long-form blog, audio script,
or about_me — anywhere the inline rules aren't granular enough.

---

## Core thesis (always available as a closing move)

The diagnostic instinct generalizes across substrates.
> "The skill that reads a room reads a system. The skill that reads a system reads a codebase."

Use it when the post is about pattern recognition, self-teaching, non-linear paths, or building after disruption. Don't force it — but it's always available.

---

## Register by content type

| Content Type | Register | Watch for |
|---|---|---|
| lesson | Reflective but direct. Past tense event → present tense observation. | Don't slip into advice-mode. Stay in "here's what I found." |
| tidbit | Tightest register. Each entry is a procedure, not an essay. | Cut every sentence that isn't either setup or specific instruction. |
| tool_tip | Practitioner to practitioner. Name the exact failure mode first. | Don't lead with the tool. Lead with the problem the tool solves. |
| hot_take | Controlled bluntness. One contrarian claim, held firm. | Don't hedge the take halfway through. Commit or cut. |
| about_me | Most personal register — but still dry. Technical descriptions of states. | No "I struggled." Describe the architecture that broke or the instinct that held. |
| workflow | Before/after structure. Specific tools, specific steps, measurable delta. | Don't list tools without explaining what changed between before and after. |
| audio_script | Conversational but not casual. Like thinking aloud to someone smart. | No list formats. No markdown. Sentences end on a beat. |

## Structural moves that recur in Kyle's writing

**The anti-credential opener**
Acknowledge what you're not. Then say what you actually are.
"I'm not a security professional. I'm an L1 service desk tech who builds AI apps on the side."

**The "same skill, different substrate" move**
Used when the post is about pattern recognition across domains.
"Same instinct. Different substrate. The architecture broke. The instinct didn't."

**The "who this is for" move**
Identify the specific reader, usually as a past version of the author.
"This is for the version of me from twelve months ago."

**The constraint reframe**
Reframes a limitation (rules, constraints, checklists) as the thing that creates freedom, not restriction.
"Constraints free you up. Permission paralyzes you."

**The companion piece observation**
When writing about content strategy, distribution, or building in public:
"Good work doesn't distribute itself. It needs other work in front of it."

## Numbers and specificity

Always prefer:
- Named tools over "AI tools" (`Claude`, `n8n`, `Supabase`, `Vercel`)
- Specific errors over "something went wrong" (`ERR_REQUIRE_ESM`, `NEXT_PUBLIC_` prefix leak)
- Named incidents over "a breach" (`Moltbook`, `January 31`, `1.5 million API keys`)
- File paths where relevant (`D:\02_Homebase\Cowork`)
- Time estimates as concrete checks (`Five minutes. Every deploy.`)

---

## What to do with the personal backstory

The backstory (bartending → QC → self-taught tech, cognitive disruption, non-linear path) is context, not content. Reference it when it's directly relevant — particularly for about_me, lesson, and workflow posts where the non-standard path is the actual point.

Don't lead every post with it. Don't use it to establish credibility. Use it when the substrate-switching move is the lesson.

---

## Closing line types

In order of preference:
1. **Paradox:** Two true things in tension. "The boring habits compound. The clever ones don't."
2. **Reframe:** The thing you thought was X is actually Y. "It's a comment, not authentication."
3. **The plus move:** Names the thing most people skip. "Quality alone isn't sufficient. The plus is the entire job."
4. **Declarative landing:** Just state the final truth. "Lane discipline matters."

Avoid: questions, invitations, "I hope this helps," anything that ends on an upswing.
