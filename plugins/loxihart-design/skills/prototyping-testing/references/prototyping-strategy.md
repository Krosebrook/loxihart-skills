# Prototyping Strategy Selection

**Rule:** Use the lowest fidelity that answers your question. Every fidelity level up costs time. Match fidelity to the question being asked.

## Prototype Types

| Type | Build time | Use for | Tests |
|---|---|---|---|
| Paper / whiteboard (lo-fi) | Hours | Idea generation, team alignment, early concept testing | Layout, flow, mental models |
| Wireframe clickable (mid-fi) | Days | IA validation, flow testing, stakeholder alignment | Navigation, content hierarchy, task completability |
| Visual mockup (hi-fi, static) | Days | Stakeholder sign-off, design review, handoff | Visual design, brand alignment |
| Clickable prototype (hi-fi, interactive) | Days–week | Usability testing, investor demos, user acceptance | Full task flow, error recovery |
| Coded prototype | Days–weeks | Performance validation, complex interactions, technical feasibility | Animation, data loading, edge cases |

## Decision Matrix

| Question | Recommended |
|---|---|
| Is this the right concept? | Paper / sketches |
| Can users navigate this? | Wireframe clickable |
| Will users understand this screen? | Static mockup |
| Can users complete the task end-to-end? | High-fidelity clickable |
| Does this perform acceptably? | Coded prototype |

## Workflow

1. **Clarify** — what stage is the design at, what questions need answering, timeline, resources available
2. **Choose fidelity** — lowest that answers the question; document the rationale
3. **Define scope** — which flows, screens, and states will be prototyped
4. **Select test method(s)** — appropriate to the questions (see other reference files)
5. **Define participants** — who to recruit, how many, screener criteria
6. **Build timeline** — prototype build → recruit → sessions → analysis → readout
7. **Specify decisions** — what will this unblock? Who needs the results and when?

## When NOT to build a prototype

- The question is structural, not behavioral → run a tree test or card sort instead
- The question is visual, not interactive → a static screenshot is sufficient
- The concept hasn't been defined yet → stakeholder alignment workshop first
