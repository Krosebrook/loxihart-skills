# Framing Patterns — Loxihart Leadership Communications

## The translation table (use it every time)

| Don't lead with | Lead with |
|---|---|
| "Deployed an MCP server for FreshService" | "Ticket lookups that took 4 clicks now happen in the chat where the tech already is" |
| "Built a skills library" | "New techs get senior-tech process knowledge on day one" |
| "Claude Teams seat, $30/mo" | "The one confirmed, zero-unknown ask in the business case" |
| "n8n workflow automation" | "The Friday report that ate an hour now sends itself" |
| Model names, token counts, architectures | Time saved, tickets resolved, risk reduced, adoption rate |

## Structural patterns

- **Ask-first:** state the ask in the first two sentences, then support it.
  Leadership briefs are not mystery novels.
- **One page.** If it doesn't fit, the thinking isn't done. Appendix links
  for anyone who wants depth.
- **Sourced or blank:** every number is vendor-published, Loxihart's own data, or
  a blank input labeled for the owner to fill. No third category. Cite inline.
- **The Dot standard:** names spelled right, dates right, zero ambiguity in
  who does what next. A sloppy brief about precision tooling refutes itself.
- **Status pattern (recurring updates):** Shipped / In motion / Blocked /
  Ask. Blocked items name the unblocker by name.

## Anti-patterns

- Burying the ask after the context
- "Industry studies show…" without a checkable citation
- Aspirational title framing — Kyle is an L1 Service Desk Technician whose
  AI work is self-initiated; the work carries the brief, not a title
- Ending without a next step + owner + date
